# DSBotDeck

DS-Bot 聊天与设置的独立桌面客户端，首版面向 Windows 10/11。

只用于查看和管理远程服务器上的 DS-Bot，不提供远程电脑画面、键鼠控制或电脑/浏览器接管。权限按原配对身份与服务器授权决定，Deck 不额外强制 Windows Hello。

> 本轮源码版本为 `0.1.6`，在已发布 `0.1.5`（`288175f`）上增加窗口/配置变化诊断，用日志定位退出重开逐次变大的首次不一致；不再猜测尺寸补丁、不重置原配置。旧 `0.1.5` 不会生成新日志，类型、回归和安装包须核对 `0.1.6` 对应的 Actions。代理本机仅做静态核查，不安装依赖、构建、启动应用或运行测试；CI 也不能代替 Windows 实机诊断。步骤见 [远程客户端验收](docs/verification/remote-client.md)，取日志方法见 [窗口配置变化诊断](docs/verification/window-diagnostics.md)。

## 做了什么

- 聊天、Bot 详情、设置、主题与动效复用 DS-Bot 原有组件，不另画一套管理界面。
- 普通聊天、群聊与后台任务默认显示“用了 N 个工具”，点击展开或收起工具原名、本地化说明和成功/失败/未确认。后台任务仍可用原“显示步骤/隐藏步骤”按钮切换。实时状态显示服务器报告的当前工具原名，计时仍是当前轮次时间。
- 普通 Bot 私聊在输入框上方显示当前会话的工具审批，复用原卡片和服务器接口，提供“允许一次／拒绝”；群聊和后台任务沿用原审批。不会自动授权，不把一次许可变成永久权限。
- 添加服务器和重新配对支持导入或粘贴 PNG、JPEG、WebP 二维码截图；本机识别后填入链接，用户确认才连接。
- 不显示电脑控制设置页、Bot 的“Control”卡和电脑/浏览器详情标签；保留聊天附件、工具调用记录及普通 Bot 设置。浏览器权限配置仍属于 Bot 设置，不是浏览器接管。
- 左侧是多服务器树，包含主 Bot、上游分组、Bot、群聊、搜索、折叠和宠物关注。整栏可收成窄栏，并记住展开状态；窄栏仍显示 Bot／群聊头像，悬停显示所属服务器和名称，点击直接切换。
- 左下角齿轮打开 Deck 本机设置；各服务器行悬停齿轮打开对应服务器设置，Bot/群聊行齿轮及聊天顶部名称打开原参数页。
- Deck 设置集中原主题/明暗模式、程序图标、全窗口背景、原 DS-Bot 界面语言和宠物显示/锁定/置顶/外观。只影响本机，不改写远程主题或头像。
- 每台服务器独立配对身份、Relay 令牌和 Chromium partition，同时保持自己的加密连接。
- 管理操作按原配对与服务器权限发送，不额外要求 Windows Hello；取消、切换后再切回、重开界面、缓存或连接代次变化仍不发送旧请求，不自动重发。
- 四色宠物：绿＝运行，黄＝待交互，红＝明确失败，蓝＝完成待查看。断线保留缓存，不把网络失败算作红灯。
- 主体可拖动；锁定只穿透主体与标签，灯、气泡和工具按钮仍可操作。右侧竖排显示非零四色灯和清楚的数字徽标，小灯与状态标签可有底色，宠物不变淡。顶部打开主窗口/设置仅悬停宠物时显示，移向按钮保持可点、离开隐藏。气泡由灯打开，随宠物位置在本屏工作区上方或下方展开，限高滚动；换边保持宠物桌面锚点，离开灯和气泡 10 秒后隐藏。缓存暂停动画并提示，不淡化宠物。
- 关闭主窗口只隐藏到托盘；退出只关闭客户端连接，不停止远程 Bot。主窗口记住位置、大小和最大化状态，最小化退出保留最后有效布局；显示器断开后移回可见工作区；Win+方向键半屏贴靠及重启恢复不再被960px最小宽度撑开。

四色数字统计的是关注对象数，不是模型重试数、网络重连数或后台任务总数。同一对象的多个后台结果分别确认；打开聊天不等于查看了后台任务结果。默认关注当前可显示的 Bot 和群聊，隐藏对象除主 Bot 外不默认关注。宠物首次启动默认隐藏，可从 Deck 设置开启。

## Deck 本机设置

- **原主题与明暗**：复用 `DeepSeek`、`Mono`、`Paper`、`Moonlight` 的原预览组件和配色；选择浅色、深色或跟随系统，默认 DeepSeek／跟随系统。主窗口、聊天和宠物统一，切服务器不改变主题，固定模式不随系统变化；只保存本机选择，不写服务器主题配置。
- **图标**：默认应用标记为原 `star/aurora` 五角星渐变，新的 EXE 与安装包图标也由同一矢量生成（0.1.5 新增）。可另选 DS-Bot 内置形状/配色或本机 PNG、JPEG、WebP、ICO，已保存的自选图标不被覆盖。设置用于侧栏 Logo、欢迎页、窗口、运行任务栏和托盘，并尝试同步当前安装的开始菜单入口；只更新图标属性，不改启动目标或参数，不改写已有 EXE。可点“重新应用图标”重试同一图片，失败提示且不提权、不清系统缓存；已固定项可能需取消固定后重新固定。服务器、Bot 头像和宠物选择不变。
- **背景**：选取本机 PNG、JPEG 或 WebP，连续铺满整个程序窗口（包含聊天区），不读取服务器背景。可调透明度、模糊与填满/完整显示；“选择背景位置”提供与当前窗口同比例的选框，可拖动、缩放或用方向键微调，点击“应用选区”后显示框内区域。窗口变化保持所选中心并等比适配，选区保存在本机；“恢复整图”取消裁剪，换图清空旧选区，不改写原图。“其他区域背景透明度”控制侧栏等区域；会话区透明度比它低 **10 个百分点**，最低 0%，例如其他区域 60% 时会话为 50%。文字、控件和宠物不随之变淡。移除图片即可回到原主题底色。
- **原 DS-Bot 界面语言**：默认简体中文，可选择上游支持的语言或跟随本机系统；切换后原聊天控件、Bot 参数和服务器设置使用本机选择。Deck 自身说明保持简体中文，不翻译工具原名、聊天正文或模型名，不改变 Bot 回复语言。
- **宠物**：显示、主体锁定、置顶、尺寸和外观都在这里设置。内置宠物可独立选择 DS-Bot 形状和配色，也可选 Codex 精灵。参考 `pet-e` 的视觉布局独立实现右侧竖灯、小状态标签和任务卡，不复制运行器、代码或素材；小控件可有底色，宠物主体保持原不透明度。气泡根据所在显示器的工作区自动上下换边，中线附近防抖，旧位置记录兼容；仅悬停出现主窗口/设置按钮，非零灯和十秒收起规则保留。

### Codex 宠物合集

默认只读 `%USERPROFILE%/.codex/pets`，也可在 Deck 设置中用本机选择器更换目录并刷新。每个直接子目录应含 `pet.json` 和其 `spritesheetPath` 指向的 WebP；兼容标准 `1536×1872`（九行）及 `1536×2288`（十一行），不运行目录中的脚本。

合集只扫描前 256 个目录项，逐项检查路径、类型、大小与精灵尺寸；坏包标为不兼容，不影响其他宠物。扫描只读文件头，完整精灵仅为选中项读取，素材不复制进仓库或安装包、不上传服务器。图片缺失或损坏时回退内置外观，保留选择及原配对身份。

当前用户合集静态核对为 121 项：120 项标准九行，1 项为 `256×80`，会标为不兼容。此数量不是安装包自带的宠物数量。

## 独立目录与上游

默认目录结构：

```text
D:/Project/DshDeck/
  DS-Bot/       上游，只读
  DshDeck/      现有客户端，不修改
  DSBotDeck/    本项目
```

本项目不启动或打包本地 DSH、Agent、Python、Office、终端或 Bot Host，也不监听 HTTP 端口。

构建时只读引用：

- `../DS-Bot/app/ui/src`：独立界面入口、聊天、团队数据源、语言和 primitives。
- `../DS-Bot/ds-bot/src/client`：原组件、样式、主题与管理动作。
- `../DS-Bot/link/src`：手机端同一套 Relay、Noise 加密、主机身份核对与 Bot RPC。
- `../DS-Bot/mobile/src/team/gated.ts`、`notices.ts` 与浏览器端点权限定义：敏感门禁和 notice 续读规则。

参考提交为 `d104d9ca18d69a35460f14e15dff4d553181433a`，对应 DS-Bot `0.3.10`，远程 API 为 `1`。构建产物的 `dist/upstream-sources.json` 记录实际上游提交、参与构建文件与 SHA-256，来源记录不含绝对路径或客户端凭据。

`app/ui` 是上游已有但当前暂停打包的入口。上游接口变化时，本项目的兼容检查会停止构建，不自动改上游。需要时只调整本项目的适配。

构建仅在内存里替换入口、primitives、结果呈现回调，接入共享只读工具摘要和普通私聊的原审批卡、导出原主题预览并由本机设置接管明暗，并隐藏本客户端不需要的电脑/浏览器控制入口，不产生上游补丁或 UI 副本。上游 Windows CRLF 与 LF 换行均可接入。结果呈现回调不改变原内容的视觉，只用于确认蓝灯对应的内容确实已显示；工具条使用原任务步骤样式和主题变量。上游电脑控制开关和 Bot 配置保持原样，不因入口隐藏而被关闭。

## 工具过程与数据边界

主聊天及群聊通过原 `chat` / `room-chat` 请求的 `steps: true` 读取步骤，后台任务使用原 `bot-task-read`。工具摘要展示的是服务器公开的条目，不绕过上游隐藏轮次、私密 Bot 或配对权限。

- 实时状态取 `state.work` 的当前工具名，群聊注明成员；追加输入不会把仍在执行的工具盖成泛化思考文案。只有服务器未报告当前工具时才回到原思考状态，不把历史“未确认”步骤当作运行证据。
- 每轮先显示工具数量，默认折叠；点击标题或聚焦后按 Enter/空格可展开，再次操作收起。展开只改变本机显示，不额外发 RPC。
- 保留工具原名和返回顺序，不把重复调用合并成一次；缺少名称明确显示“工具名未提供”。
- 只有 `ok: true` / `ok: false` 才显示成功/失败；缺结果显示“未确认”，不推断仍在运行，不把单次工具失败当成整个任务失败。
- 不显示虚构的完整参数、具体文件路径、执行命令或工具输出。上游摘要没有这些字段，不能靠取消隐藏恢复。
- `steps.ms` 是该轮思考时间，不是单个工具耗时；工具条不据此计时。
- 工具变化通知按一秒合并；只刷新原读取上下文仍有效、可见且非缓存的聊天。隐藏、换 Bot/分段、断线或卸载后清理排队读取，返回可见页面时复读最新内容。

这是只读查看 Bot 的公开过程，不是远程控制电脑。旧服务器不返回步骤时不生成替代记录。

## 用户准备与启动

需要 Node.js 24 及本项目 `package.json` 中的依赖。初次准备依赖会联网下载 npm 包和 Electron，须由你自行执行；不要在两个相邻仓库中安装本项目依赖。

```powershell
Set-Location D:/Project/DshDeck/DSBotDeck
npm install
npm run typecheck
npm test
npm run build
npm start
```

以上命令本轮均未执行。`npm run typecheck` 是严格类型检查，不能以本轮 `node --check` 的语法解析替代。

`npm run build` 的默认图标步骤会用本项目已有 Electron 打开隔离隐藏转换页，只绘制上游原五角星向量；profile 和中间 PNG 均在专用临时目录，完成后清理。它不加载 Deck 主入口、用户身份库或远程连接，不启动 Bot。输出仅为本项目 `dist/assets/` 的 PNG/ICO；图标来源文件继续写入内部来源记录。此步骤由用户或 CI 执行，代理没有运行生成器。

独立 Windows x64 安装包由用户执行：

```powershell
npm run dist
```

安装包输出到 `release/`，不自动发布。卸载不会自动删除客户端数据。

如只为构建指定其他上游目录，可在当前 PowerShell 会话设置：

```powershell
$env:DSBOT_SOURCE = 'D:/Source/DS-Bot'
npm run build
```

默认的类型检查路径和源码兼容回归以相邻 `../DS-Bot/` 为依据。改变布局时，也需在本项目 `tsconfig.json` 和回归源码定位中同步路径，不改上游文件。更新上游后重新构建，安装后的客户端不需要旁边放一份上游仓库。

## GitHub Actions 构建

工作流见 [build.yml](.github/workflows/build.yml)。需要把 `DSBotDeck/` 的内容作为独立 GitHub 仓库根目录提交并上传，GitHub 才能识别根目录下的 `.github/workflows/`；只把整个 `DSBotDeck/` 放进另一个仓库的子目录不会自动识别。不要为此修改相邻两个仓库。

- `main` 上的源码、构建配置和工作流变更会触发构建，也可在 **Actions → Windows 客户端构建 → Run workflow** 手动启动。
- `upstream_ref` 留空时使用参考提交 `d104d9ca18d69a35460f14e15dff4d553181433a`；可填官方上游的提交 SHA、分支或标签。变更后仍须通过唯一锚点兼容检查，不能强行跳过。
- Windows runner 把客户端检出到 `DSBotDeck/`，官方 `Fei2411/DS-Bot` 只读检出到同级 `DS-Bot/`，只在客户端执行 `npm install`、`npm run typecheck`、`npm test`、`npm run dist`。不在上游安装依赖或启动 DSH。
- 工作流只需要 `contents: read`，Actions 引用固定提交，两次检出均不持久化凭据。不发布 Release、不部署服务，也不自动提交 CI 生成的文件。

成功后下载 `DSBotDeck-Windows-x64-<run_number>-<run_attempt>` Artifact，解压只有 `DSBotDeck-Setup-0.1.6-x64.exe`（Windows x64 NSIS 安装包）。GitHub 的 Artifact 下载会套一层 ZIP，但里面不再包含源码 ZIP、依赖解析记录或其它单独附件。

构建内部仍核对 `dist/upstream-sources.json` 的提交与实际上游一致；完整 LICENSE/NOTICE、上游归属和来源记录继续随安装包保留。runner 生成的依赖解析记录不自动回写仓库，目前依赖尚未通过提交锁文件完全锁定。

本机开发阶段仅做静态检查，没有生成安装包。提交并推送源码后，工作流才会自动执行；源码上传不代表 CI 已经通过。工作流未配置代码签名，CI 成功也不能替代实际配对权限、原 UI、真实服务器与宠物交互的实机验收。

## 配对与权限

1. 在服务器本机启动 DS-Bot，并开启原“手机访问”。
2. 完整远程管理须使用手机配对二维码对应的 `dsbot://pair` 文本。云电脑无法复制时，可截取二维码，在“添加服务器／重新配对”点“从截图识别二维码”选择 PNG、JPEG、WebP，或在链接框粘贴图片；只在本机解码，识别后仍需点击保存。支持原浏览器链接片段，但不提升浏览器权限；没有码、非配对码、损坏/超预算图片会提示，失败不清除原链接。
3. 上游“复制浏览器链接”也可以配对，但始终只有浏览器权限。取消 Deck 的额外本机验证也不能将浏览器设备升级为手机权限。
4. 浏览器设备升级完整管理时：在服务器本机撤销旧设备，客户端先“忘记本机连接”，再用手机配对码新添加。不得通过重新配对旧浏览器身份提权。
5. 默认最多保存 32 台服务器，每台使用自己的设备身份，避免同一个 Relay 的设备注册相互挤掉。

客户端已在加密握手中发送设备名称 `DSBotDeck（Windows）`。原服务器连接页对浏览器权限设备固定显示“网页浏览器”，会忽略这个名称；仅升级 Deck 不能改变该后台页面。按上游只读约束，本项目仅提供 [后台设备名称修改说明](docs/verification/server-client-name.md)，没有修改服务器的界面、设备记录或权限。

优先使用 `wss://`。自建 `ws://` 沿用上游允许的形式，但中转注册认证令牌没有 TLS 保护；Bot RPC 正文仍经过 Noise 端到端加密。只在你明确理解该风险的可信网络使用。

客户端支持远程链路允许的管理动作。设备配对管理、MCP 接入配置、电脑权限、本机目录选择与数据搬移等本机专属动作不发出远程请求。服务器端仍作最终授权，客户端不绕过它。远程工作目录使用原 FolderMenu 的浏览模式，浏览的是服务器目录，不是客户端磁盘。

电脑控制、电脑/浏览器实时画面与接管端点在客户端主进程一律拒绝，手机配对与浏览器配对都不能启用，拒绝时不弹 Windows Hello、不发 RPC。聊天中的已记录截图附件 `computer-shot` 保留上游原有配对权限和验证门禁，它只按附件 id 读取已保存图片，不采集实时桌面。原独立 UI 没有提供的本机浏览器、终端或语音宿主桥接也不会被注入；本项目不是远程桌面或本机工具执行环境。

### Bot 工具审批

普通私聊只显示当前 Bot、当前会话、仍可回答的工具审批；服务器公开的工具、原因和请求文本/代码显示在原审批卡内。点“允许一次／拒绝”只通过原 `approval-answer` 回传请求编号和选择。群聊、后台及旧会话不混入私聊卡，过期或已由其他客户端处理的请求不自动重发。

这是服务器上本次工具调用的许可，不是客户端电脑提权、Windows UAC、远程键鼠接管或永久授权。审批公开的请求说明也不等于完整历史工具参数与输出；后者仍取决于服务器接口。提供方密钥接口只返回是否已配置、是否可写等状态，不回读原始密钥，取消本机验证不能恢复 `***`。

## 安全与数据

客户端配置位于 `%APPDATA%/DSBotDeck/client.vault.json`，整体使用 Electron `safeStorage` 的 Windows 系统加密。它与 DS-Bot、DshDeck 的数据目录分开。旧 `0.1.0` 配置会补充默认外观字段，已有窗口矩形按未最大化读取，不重新配对、不重建身份。自定义运行任务栏图标只在该用户目录下生成图标缓存，不改写选中的原图。

- 配对私钥与 Relay 令牌只在主进程使用，不进入公开快照、渲染进程或日志。
- 加密不可用、文件不能解密、私钥与公钥不匹配、主机身份不匹配或令牌损坏时拒绝读取或连接，不生成替代身份覆盖原记录。
- 一次性配对码只用于这次加密握手；设备身份先加密保存，握手成功后即确认配对，不因后续读取失败丢失身份。
- 各服务器的请求绑定原服务器、界面实例与连接代次。验证前冻结 payload，验证后再次核对，不自动重发写入。
- 网络超时可能意味着服务器已收到操作；查看服务器状态后再决定是否手动重试，不能把超时当作“没有执行”。

标准入口不装配 Windows Hello 验证器，不要求配置 PIN，也不伪造 `Verified`。按你确认的使用方式，能操作当前已解锁电脑上的 Deck 的人，可以执行已配对身份允许的管理动作；请自行锁定电脑并在服务器撤销不再使用的设备。加密保存、服务器授权、缓存禁写、取消与上下文检查继续保留。

“忘记服务器”只删除本客户端保存的连接身份并关闭对应界面，不撤销服务器端设备，也不承诺擦除 Windows 文件历史或该 partition 的界面偏好。撤销设备须在服务器本机操作。

## 验证与已知边界

本机仅做语法、UTF-8、JSON、PowerShell、源文件引用及权限/状态链路的静态审查。回归和编译由对应提交的 Actions 验证；默认无额外本机验证下的配对限制、两服务器实连、普通私聊审批、语言切换、背景连续性、Windows 图标刷新、窗口贴靠、托盘、鼠标穿透、上下气泡、多显示器拖动和 Codex 精灵视觉仍待用户验收。

专用多代理代码审查没有运行：当前工具未提供子代理或原生 review。本版针对 `a9f3db5` 之后的差异补充了复用、质量、效率、权限与失败路径的手工审查，不将其称为独立模型复核。没有调用外部模型、自动发布或创建后台验证服务；提交与推送只记录和上传源码，不代表测试、构建或实机验收已通过。
