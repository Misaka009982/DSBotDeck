# DS-Bot 后台设备名称显示说明

## 当前状态

本说明**尚未应用到服务器**。本轮按用户选择保持 `DS-Bot/` 和 `DshDeck/` 只读，没有修改服务器界面、设备记录、权限或密钥，也没有部署或重启远程服务。

DSBotDeck 已在加密握手中发送：

```js
hello: { name: 'DSBotDeck（Windows）' }
```

对应本项目 `src/main/link-factory.ts`。这个名称是显示信息，不是额外的授权身份；每台服务器仍沿用自己的设备密钥与配对权限。

## 为什么后台统一显示“网页浏览器”

当前参考上游 `d104d9ca` 的 `link/src/pairing.ts` 会在首次配对时保存 `hello.name`，`ds-bot/src/host/phone.js` 会把设备名称传给连接页。

但 `ds-bot/src/client/phone-page.js` 的设备列表使用：

```js
label: entry.kind === 'browser' ? t('Web browser') : entry.name || t('Phone'),
```

因此浏览器权限设备的名称被忽略。即使服务器已保存 `DSBotDeck（Windows）`，该页仍显示“网页浏览器”。这不是 Deck 没有发送名称，也不是缺少一套新的配对密钥。

## 服务器界面的最小修改建议

在服务器实际部署版本的连接页中，只把这一行改成先显示已有设备名称，空名称仍回退为类别：

```js
label: entry.name || (entry.kind === 'browser' ? t('Web browser') : t('Phone')),
```

其余连接状态、配对日期、移除按钮和设备 `id` 保持不变。可以另外显示原权限类别作为提示，但不要修改 `entry.kind`、`DeviceRegistry` 的授权判断或浏览器端点白名单。

名称只能作为普通文本展示，不能据此信任客户端或放宽权限。不要新增 `desktop` 权限类别，不要让浏览器配对冒充手机，也不要为改显示名删除或重新生成设备身份。

## 部署注意事项

- 修改需要作用于**云服务器实际运行的 DS-Bot 版本**，不是本机只读参考仓库。
- 按服务器现有的构建和部署方式更新界面资源；只改源码而没有更新正在使用的 `client.js` 等资源，浏览器页面不会变化。
- 构建、部署和必要的服务重启由服务器管理员自行决定并执行，本轮未执行这些操作。
- 无需改变 Relay 地址、配对方式或 Deck 的连接模式，也不应因为显示名改动而重新配对。
- 旧设备如果没有保存名称，页面仍应显示通用类别。当前协议对已配对设备的重新握手不会自动更新已保存名称；这种情况需要服务器提供受约束的名称更新功能，不能靠客户端替换密钥解决。

## 验收

1. 已保存名称的 Deck 浏览器权限设备显示 `DSBotDeck（Windows）`。
2. 普通网页设备继续显示其原名称；名称为空时显示“网页浏览器”。
3. 手机设备的原名称、在线状态、配对日期和移除行为不变。
4. Deck 重新连接后使用原设备记录，不出现多出的配对设备。
5. 浏览器权限仍不能调用原本禁止的敏感端点，名称不影响授权。

仅升级 Deck 安装包不能改变未更新的服务器后台页面；不要把本说明视为后台身份显示已经修复。
