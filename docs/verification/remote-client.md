# DSBotDeck 远程客户端验收

## 当前证据边界

此文以已发布 `0.1.3` 的 `6d402da` 为基线，本轮 `0.1.4` 在已有主题工作上补充普通私聊工具审批、参考宠物呈现与上下气泡，并按用户确认取消额外强制 Windows Hello；类型、回归和打包结果须按本轮源码提交独立核对，原 `0.1.3` Actions 不能证明本轮检查已通过。客户端只用于 DS-Bot 聊天与设置，不提供远程电脑或浏览器接管，不因隐藏控制入口而关闭服务器能力。当前本机没有安装依赖、执行 TypeScript 类型检查、构建、启动 Electron、运行测试、调用 Windows Hello、连接 Relay 或打包安装程序；类型、回归与打包结果须按新提交独立核对。

“源码已交付”和“客户端可以正常使用”是两个不同结论。只有用户完成下述运行项，才能得出后者。

### 已做的静态检查

- 98 个项目文本为 UTF-8；2 个 JSON 可解析。
- 使用 `node --check` 只解析 75 个 JS/MJS/TS 文件，并对本轮 2 个虚拟审批接入源码解析语法，不执行模块、应用或回归。本机没有 TypeScript 依赖，不安装新依赖，也不把语法结果称作严格类型检查。
- 定义了 24 个回归文件、137 个 `test()` 用例，本机没有运行；新增普通私聊审批筛选、原卡只读接入、允许一次/拒绝回传、过期/切服/断线不重发；新增宠物上下布局、中线防抖、原生拖动锚点与旧位置兼容；补默认无额外验证时的配对权限和导航 ABA。前面的主题、持久化、监听清理和透明度差值回归保留。
- 类型检查保留 `NodeNext`、`strict` 与完整库类型检查；只将上游使用的 4 个加密模块映射到客户端已声明依赖的具体 `.d.ts` 入口，不使用无扩展名目录或通用 `@noble/*` 映射，避免改写 `clatterjs` 自身的嵌套依赖。真实 ESM 解析回归已定义，结果以 CI 为准。
- 内部/上游引用与工具/角色构建别名核对；新增本机素材/设置事件仍受主窗口或宠物发送者归属限制，不对远程页面开放文件系统或任意 IPC。二维码 Worker 同样使用只读别名，主线程仅绘制像素。npm 外部包仅核对声明与公开类型，本机未安装或作运行解析。
- Codex 合集只读核对 121 项配置和 WebP 文件头：120 项标准九行，1 项尺寸不兼容。没有运行图片解码或复制、上传素材；本机读取实现有文件大小、像素、目录与扫描预算，坏包回退及旧配置默认值已定义回归。
- 原 Windows Hello 脚本此前通过 PowerShell AST 语法解析；本轮未修改或执行。标准入口不再装配 WindowsUnlock，不伪造 Verified；可选验证器仍保留供显式集成与回归，不参与标准运行。
- 固定正式版 `d104d9ca` 的 28 个接入锚点通过静态唯一性核对：原 19 个、实时工具 3 个、主题 2 个和本轮私聊审批 4 个；只读取 Git 对象，不 checkout 或改写上游。
- 本轮另外只读导出 ThemeGallery 并移除入口的强制系统明暗监听；CRLF 规范化、唯一锚点检查和上游原文件不变保留。本机主题只传标识与明暗模式，不向远程视图提供本机素材路径。
- 工具摘要三态、名称与本地化说明、未知结果中性色、固定目标、可见性/缓存门禁以及一秒合并刷新和清理已作源码审查；未进行 React GUI 验证。
- `.github/workflows/build.yml` 的缩进、触发器、固定提交、最小权限、双 checkout、执行顺序和内嵌 PowerShell AST 静态核对通过；本机没有执行工作流，也没有把结构审查称作完整 YAML/actionlint 或 CI 验证。
- 电脑控制与浏览器画面/接管在两种配对模式均由主进程直接拒绝，不进入系统验证或 RPC；普通聊天、Bot 设置、历史附件及其原有权限门禁保留。
- 主进程设备身份、公钥与私钥核对、加密失败关闭、独立 partition、固定服务器/界面实例、请求冻结和导航/连接代次核对已作源码审查。
- 检查旧连接事件、同代次旧状态成功/失败回包、状态读取单飞、局部恢复、不重发写入和 notice 基线。
- 检查蓝灯的成功读取凭据与原 Chat/TaskReaderView 可见布局匹配，不以点击、选中或单纯请求成功代替“已看”。
- 检查宠物只采样本机桌面坐标，锁定只穿透主体、控件优先、气泡离开灯与面板 10 秒关闭；新布局绑定指针与命中区代次，换边保持本体桌面锚点，保存旧版画布原点格式。
- 本轮没有写入相邻仓库或参考目录。`DshDeck/` 仍干净；相邻 `DS-Bot/` 已有另一个 `feat/stable-addons` 任务的未提交增补，当前工作树的聊天读取锚点与原版不同，兼容检查会停止。原版静态核对使用固定 Git 提交，不把增补工作树当作 Actions 的原版源码。

首版源码已有复用、质量、效率、正确性、权限和协议审查。本轮在已有未提交主题工作的 `feat/local-themes` 上追加授权范围内的审批、宠物和标准入口验证调整，按增量进行手工核对，不重构重叠文件里的主题工作。已核对原卡复用、服务器公开数据边界、可选验证器不进入标准入口、固定目标/缓存/代次、布局原点与监听释放，并避免指针采样重复读取配置。当前工具没有子代理或独立模型审查能力，专用多代理审查未运行；静态语法和手工审查不能替代类型、行为或安全实机验证。

上一版在已通过 CI 的 `249a710` 上接入真实工具状态、宠物非零灯与悬停工具栏、原角色与配色、折叠侧栏头像、透明窗口按钮及本机二维码截图导入。复用 `CharacterGrid`、`BotMark`、原路径与配对验证；不修改上游服务器。二维码线程退出时终止、关闭弹窗取消解码，图片不写入日志或网络；内置图标 PNG 有尺寸和字节预算，只通过固定本机资源路线提供，公开快照不重复传整张图。WebP 图标由 Chromium 转为 PNG 再交给原生窗口，响应绑定素材 revision，旧图片不能覆盖新选择；WebP 背景沿用 Chromium 显示。当前服务器的 `steps` 只返回名称/说明/可选布尔结果，完整参数输出仍待服务器接口支持；未把摘要提示当成详情已完成。

## 用户运行顺序

本轮保留原主题/明暗选择与透明度差值修改，并补齐输入框上方的普通私聊工具审批、右侧非零四色灯、小状态标签、上下自适应气泡；取消的是 Deck 额外强制 Windows Hello，不是服务器或配对权限，也不新增自动或永久授权。后台客户端名称仍只提供 [服务器修改说明](server-client-name.md)，本轮没有修改上游连接页、权限或配对。

`0.1.3` 新增背景选区与开始菜单图标同步，修正半屏贴靠被最小宽度撑开。选区只保存归一化中心和1–8倍缩放，窗口变化重新适配比例，不写原图；开始菜单只更新目标为当前 EXE 的既有入口图标，失败提示且不提权，默认图标指向真实 EXE 而非 asar 路径。两个原仓库仍只读。第6轮 Actions 的严格类型检查发现 `ShortcutDetails.target` 是必填项，已在 `update` 时传回刚读取并核对的原始目标，保留原路径字面值与其余启动属性，不使用类型断言绕过检查；实际通过状态以修正提交后的工作流为准。

只在本项目准备依赖；不要修改相邻仓库的环境。当前相邻 `DS-Bot/` 是增补工作树，不能直接拿来证明原版兼容；本机若要执行下面的验证，应先由用户准备独立的 `d104d9ca` 原版只读检出并同步源码/类型检查路径，或由 Actions 按固定提交检出。不要 reset、覆盖或混用正在进行的增补任务。

```powershell
Set-Location D:/Project/DshDeck/DSBotDeck
npm install
npm run typecheck
npm test
npm run build
npm start
```

`npm install` 会联网获取依赖和 Electron；由用户决定并执行。本轮没有运行上面的任何命令。

1. 严格类型检查通过，没有用 `any`、类型断言或关闭 strict 掩盖生产代码问题。
2. 回归通过，没有访问用户真实数据目录、没有真实连接或系统验证弹窗。
3. `dist/main/index.mjs`、三个 preload、主窗口、宠物与远程 UI 资源均生成。
4. `dist/upstream-sources.json` 的提交与源码摘要正确，完整上游 LICENSE/NOTICE 存在。
5. 客户端可启动，未启动 DSH、Agent、终端、Python 或本地 HTTP 服务。

## 实机验收

### 1. 单服务器原 UI

- 服务器本机开启原手机访问，准备新配对码。
- 手机码须读取二维码内的 `dsbot://pair` 文本；浏览器链接只有浏览器权限。
- 在添加服务器和重新配对中，分别选择 PNG/JPEG/WebP 的手机码、浏览器码，或粘贴截图；只填入链接，点击保存才连接。错误码、空白、损坏和超预算图像不能清除原链接，关闭弹窗应停止识别。
- 客户端新添加后，主 Bot、上游分组、Bot 和群聊应正确出现。
- 验证聊天、群聊、详情、模型选择、模型提供方、密钥、能力、记忆、计划任务、审批、连接器和其它服务器允许的设置动作。
- 验证 Bot 换段后仍按稳定 Bot 身份导航，使用上游 `currentPart` 跟随当前段，不出现手动分段会话列表。
- 对照同一上游提交的原 UI，检查颜色、主题、头像、正文、气泡、详情/设置布局与动效。
- 左侧允许与原 UI 不同，右侧保留原组件视觉；独立外壳、缓存提示、不显示电脑控制/浏览器接管入口和默认工具摘要是明确差异。
- 设置中不得出现电脑控制页和 Bot 的“Control”卡；详情只保留普通详情与任务标签，不出现电脑/浏览器接管标签。工具总览仍能进入能力设置，浏览器权限配置、模型、记忆和任务等普通设置不受影响。
- 即使服务器已启用电脑能力，也不能使本客户端出现控制入口；服务器开关不应被客户端自动关闭。聊天中原有工具调用记录、图片和历史截图附件仍按原权限读取。
- 验证电脑/浏览器画面与接管请求在手机、浏览器配对下都被直接拒绝，不弹系统验证、不发 RPC。
- 检查代码复制、附件、目录浏览与长消息；原本依赖本机宿主桥接的功能不应静默调用客户端本机环境。

### 2. 两服务器隔离（AE1、AE3）

- 在同一个 Relay 上配对两台不同服务器；两台应有不同客户端设备身份。
- 反复切换相同名称的 Bot、群聊、详情和设置，不能串团队、已读状态、工作目录或模型。
- 验证 A 的敏感请求期间切到 B，再切回 A；旧请求仍须作废，不能因当前又是 A 而放行。
- 验证期间重新打开原界面、隐藏窗口或重建连接，旧请求不发送。
- B 的缓慢读取、断线或恢复不能把 A 切走，也不能在另一台服务器重发 A 的写入。

### 3. 原配对权限与无额外本机验证（AE2、AE3 修订）

本轮用户明确取消原 AE2 的额外强制 Windows Hello；原计划不覆盖这一新决定。先准备专门测试服务器与虚构密钥，不用生产凭据验证。

- 手机配对下，执行服务器允许且凭据可写的 `provider-key` 等操作，不出现 Windows Hello，也不启动 WindowsUnlock；不能伪造 Verified 来实现。
- 浏览器配对仍拒绝原敏感操作，不能因取消本机验证升级为手机或其他设备权限。
- 操作前取消、切走后切回、隐藏/重建界面、断线或缓存时，旧请求仍不发送；只发送到原服务器，不自动重发。
- 手机/MCP 配对管理与本机专属端点仍被拒绝，不发送 RPC；两种模式均不开放电脑/浏览器接管。
- 服务器未授权、已撤销配对或凭据由外部环境管理且不可写时，仍按服务器结果拒绝，不绕过。
- 配置页只显示密钥是否已配置/是否可写等公开状态；不能把 `***` 还原成原始密钥，保存新密钥不代表读取了旧值。

取消的是本机第二次身份验证。能操作已解锁电脑上 Deck 的人可执行已配对身份允许的管理动作，应由用户锁定电脑与撤销不再使用的设备。Bot 请求的工具许可、服务器系统权限和 Windows UAC 不会因此自动同意。

### 4. 网络和上下文（AE4）

- 正在聊天时断开 Relay，当前正文和服务器目录应保留，并出现缓存提示。
- 缓存停止运行动画，不能发送管理写入，不生成网络导致的红灯。
- 恢复只作用于该服务器。旧连接的迟到关闭、消息或旧读取不能覆盖新连接。
- 同一连接内旧状态成功或失败回包不能让新状态倒退或退回缓存。
- 敏感写入超时后不自动重发，按“是否执行待确认”处理。
- 用户手动断开后不自动恢复；配对被撤销后停止自动重试并提示重新配对。

### 5. 四色事实和结果确认（AE4、AE5）

- 真实工作显示绿；审批、提问、卡片等待等显示黄。
- 明确后台任务失败或凭据阻塞显示红；停止、中断和断线不算红。
- 客户端冷启动不把所有旧历史完成批量变蓝。
- 新消息与新后台完成出现蓝；同一对象不同任务结果分别保留待看状态。
- 只点击树、开详情或请求成功但内容未呈现，不清蓝。
- 原 Chat 或 TaskReaderView 成功显示对应最新页、进入可见区域后，只清除对应结果的蓝灯。
- 页面被设置面板遮住、窗口未聚焦、隐藏、最小化、缓存或新结果在读取后到达时，不误确认。
- 群聊后台任务的失败/完成属于群聊，不混到成员 Bot 的私聊结果中。

### 6. 宠物和窗口（AE6）

- 从 Deck 设置开启四色宠物，状态数字为关注对象数；锁定、置顶、尺寸和外观在同一设置内修改。
- 默认读取本机 `.codex/pets`，可用项能选择并显示一格精灵，异常小图须标不兼容；移走所选素材再刷新应回退原外观但保留选择，不影响配对。
- 右侧竖排灯、快捷按钮和小状态标签可有小块底色，数字与圆点清晰；宠物本体在缓存和背景透明度调整时保持原不透明度。蓝灯仍是完成待查看，不改为已停止。
- 气泡随宠物本体位置在所在显示器工作区上方或下方展开，列表限高滚动；拖动跨中线时不因画布换边跳位，不伸出本屏或压到任务栏。上下布局分别检查十秒收起和顶部按钮命中。
- 靠近左/右/上/下边缘、负坐标副屏和较小工作区时，控件及气泡应保持可见；原位置记录无需迁移，退出重开保持宠物位置。布局变化后旧命中区不能拦截桌面，旧布局指针不驱动新按钮。
- 只显示数量大于 0 的颜色灯；从 1 变 0 时隐藏灯、对应气泡与命中区，全部归零无空灯区。
- 顶部打开主窗口/设置默认隐藏，鼠标移入主体才显示；移向按钮途经间隙不消失，移出后隐藏且不拦截桌面点击。锁定穿透时也由原生指针采样触发。
- 悬停主体不打开气泡；灯打开对应颜色的对象列表。
- 指针在灯或面板内保持显示，离开两者 10 秒隐藏，重返取消倒计时。
- 未锁定时主体可拖动；锁定后主体和标签穿透，灯、气泡、工具按钮仍可操作。
- 在不同 DPI 的显示器之间拖动，宠物不应跳动；任务气泡可以跳回原服务器的原 Bot/群聊。
- 关闭主窗口不停止远程任务，托盘可以恢复；真正退出才关闭客户端连接。
- 调整窗口位置大小后立即最小化，再从托盘退出并重启，应恢复最近有效布局，不能使用最小化的临时坐标。
- 最大化后退出并重启，应仍最大化；点击还原应回到原普通矩形。普通关闭隐藏到托盘与真正退出分别检查。
- Windows 贴靠后重启应保留贴靠矩形；断开外接屏、缩小工作区后重开应回到可见范围，负坐标屏幕仍可记忆。

### 7. 许可、上游同步和安装（AE7）

- 构建前后比较 `DS-Bot/` 和 `DshDeck/` 的工作区，不能因客户端构建产生上游变更。
- 保留新的上游提交后重新构建，来源记录应变为实际提交与文件摘要；不生成上游补丁。
- 上游关键接口变化时构建应明确失败，不继续生成猜测接入的安装包。
- 用户执行 `npm run dist`，检查 `release/` 的 Windows x64 NSIS 包。
- 安装到另一目录后，没有相邻上游仓库仍能启动；只能使用打包组件，不能启动本地 DSH。
- LICENSE、NOTICE、完整上游归属和来源记录都应随产物携带。
- 将客户端作为独立仓库根目录提交并上传后，在 Actions 手动触发“Windows 客户端构建”。核对同级 `DSBotDeck/` / `DS-Bot/`、默认参考提交与可选 `upstream_ref`。
- CI 必须先完成类型与回归再打包，失败时不得为了得到 EXE 而跳过检查。下载 Artifact 后应只有 `DSBotDeck-Setup-0.1.4-x64.exe`，不含源码 ZIP、锁解析记录或单独许可附件。
- 来源提交核对与安装包内的 LICENSE/NOTICE、上游归属和来源记录仍保留；工作流不再生成对应源码 ZIP。未配置代码签名，成功打包也不能替代实机验收。

### 8. 工具步骤只读展示

- 普通 Bot 聊天、群聊与后台任务有公开步骤时，默认只显示“用了 N 个工具”；点击或按 Enter/空格展开工具原名、说明和结果，再次操作收起；后台任务原“显示步骤/隐藏步骤”按钮仍可切换。
- 同一轮摘要更新后数量应同步，已展开项不应因为普通重绘自动收起；折叠/展开不触发额外 RPC。
- 工具顺序与服务器一致，重复调用不合并；缺名称明确显示未知。只有 `ok: true` / `ok: false` 显示成功/失败，缺结果显示未确认，不推断仍在运行或整个任务失败。
- 主聊天和群聊只在原读取请求增加 `steps: true`；不得为了显示工具信息执行工具、发电脑控制端点或请求额外提权。
- 普通聊天运行 `job_output` 等工具时，状态行显示服务器报告的工具原名；追加消息后工具仍运行时不回退成泛化思考文案。群聊注明正在用工具的成员。计时仍为当前轮，不伪称工具耗时。
- 没有完整参数/输出或单工具耗时的字段就不显示；`steps.ms` 是思考时间，不能冒充工具用时。上游隐藏轮次和私密范围保持原过滤。
- 工具变化按一秒合并读取；隐藏、缓存、切换 Bot/分段或旧读取函数失效时不追加读取。返回可见页面时更新最新摘要。
- 读取工具步骤不丢掉已加载历史或错误跳动滚动位置，也不能用请求成功代替结果真实可见来清蓝。
- 查看包含电脑/浏览器工具的历史摘要不应恢复电脑控制入口；工具查看与远程控制是不同功能。

### 9. Deck 设置、外观和参数入口

- 不连接服务器也能打开左下角 Deck 设置；只有本机主题/明暗、图标、背景、界面语言和宠物设置，不发远程 RPC。
- 从 `0.1.0` 升级后，原服务器身份、选择、宠物锁定和位置保留，只补外观默认值，不重新配对。
- 点击折叠后左侧成为窄栏，展开按钮、Deck 设置、Bot/群聊头像一直可见；头像点击切换原目标，悬停显示服务器和名称；重启仍保留状态，展开/缩放时聊天视口随之重新测量，不被旧宽度遮盖。
- 各服务器悬停齿轮指向其原设置；Bot/群聊行齿轮和聊天顶部名称打开对应原参数页，不把当前分段当作稳定编号，也不误操作另一台同名 Bot。
- 分别选择 WebP 图标和背景；图标应在 Logo、窗口、任务栏、托盘一致，重启仍恢复；快速改图后旧转换不能覆盖新图。背景可显示，不应因 nativeImage 不支持 WebP 而被拒绝。
- 用 DS-Bot 原形状与配色分别更换 Deck 图标与内置宠物，确认二者独立；纯色、黑色和渐变均检查，设置不修改远程 Bot/服务器头像；与本机图片、Codex 精灵切换后重启仍保留选择。
- 选图标后检查 Logo、窗口、运行任务栏、托盘和开始菜单“推荐的项目/所有应用”；关闭并重新打开开始菜单，恢复默认后应显示 EXE 内图标。不会改写 EXE。固定项若仍显示旧图可取消固定再固定；快捷方式不存在时不创建，同名其他安装入口不修改，无权限时提示且不提权。
- 在 1366px 工作区或系统缩放125%/150%下按 Win+左/右箭头贴靠，窗口不应被撑到960px；退出后重开保持半屏宽度。跨屏、最大化、最小化后复查保存时序。
- 在背景预览拖动选框、右下角缩放、方向键微调并应用，框内内容应与全窗口背景一致；改变窗口大小时选框比例同步、中心保持且不拉伸。重启保留；恢复整图取消选区；重新选图重置旧选区，原文件不变化。
- 原主题选项复用 DeepSeek/Mono/Paper/Moonlight 的原预览与配色；在三种明暗模式逐项查看主窗口、聊天、输入区、按钮、宠物气泡与原生窗口按钮符号。固定浅色/深色后更改系统明暗不应改变；选择跟随系统后应立即恢复跟随。
- 切换主题、明暗或服务器后，草稿、已加载历史、滚动位置和参数页不应被卸载；两台服务器的原主题不同也不能替换 Deck 本机选择。重启保留，服务器原主题配置不变。
- 本机背景连续显示于外壳与聊天区，不使用服务器背景；其他区域透明度60%时会话50%，100%时会话90%，5%时会话0%。文字、控件和宠物不透明度不随图片变化，图片移除后回原主题底色。
- 右上角原生最小化/最大化/关闭按钮的普通底色透明，与窗口背景衔接；主题变更保持符号可辨，悬停/关闭红色反馈保留。
- 原 DS-Bot 界面语言默认简体中文，可切换或跟随系统；参数/设置的界面文案改变，但聊天草稿、滚动和已打开的参数页不丢。服务器偏好、工具原名、正文及 Bot 回复语言不改。

### 10. 普通 Bot 私聊工具审批

- 在专门测试 Bot 的当前私聊触发服务器工具审批；输入框上方显示原工具、原因和服务器公开请求说明，有“允许一次／拒绝”，翻看历史也能操作。
- 允许一次只通过 `approval-answer` 回传原请求编号与 `allow`，拒绝为 `reject`；不自动同意，不新增始终允许，不额外要求 Windows Hello，不在客户端执行工具。
- 当前 Bot 的旧会话、其他 Bot、群聊和后台审批不混入此卡；群聊/后台仍使用原位置，普通私聊卡不重复展示。语言、主题更新不重置草稿。
- 点击后等待原状态刷新，处理完成卡片撤回；已由其他客户端处理、过期、断线、缓存、切服或旧界面实例应报错且不自动重发授权。
- 审批说明仅来自服务器公开字段，不读取任意服务器文件，不把它当成完整历史参数/输出。电脑接管、系统 UAC 与永久权限仍不属于本功能。

## 上线后观察与回退

本版的安装、视觉及系统集成验证由用户在升级后首次使用时进行。健康信号是：旧配对直接恢复、Deck/服务器参数分工明确、背景与语言仅在本机生效、Codex 精灵不串格且控件仍可点、Artifact 仅含本版 EXE。

如果出现图片丢失或格式错误，先在 Deck 设置恢复整图、移除背景/恢复内置宠物并刷新，不删除合集或身份库；检查图标时区分运行窗口与 Windows 固定项缓存。如果出现身份丢失、串服、越过配对权限或写入重复，立即停止生产使用、保留错误及原加密配置，先用原客户端处理远程 Bot。

## 失败处理与回退

- 服务器拒绝权限：核对原配对模式、设备授权与凭据是否可写；不修改服务器权限绕过拒绝。标准 Deck 不要求额外 Windows Hello。
- 类型、测试或构建失败：保留完整 stdout/stderr，先修对应源码，不关闭 strict 或弱化断言。
- 上游接口不兼容：只修本项目适配，不改上游权限或服务代码。
- 原配置无法解密或身份不完整：停止自动连接，不删除或重建配置。先保留备份、确认是原 Windows 用户，再由用户决定恢复或重新配对。
- 新壳暂不能用：继续使用原客户端管理服务器。关闭新壳不会停止远程 Bot，也不需要回滚两个既有仓库。

真实运行的健康信号是：两服务器身份独立、原 UI 操作落在正确目标、不额外要求 Windows Hello 但仍遵守配对/服务器权限、缓存标记诚实、四色来自任务事实、取消/失败不重发写入。只要发现串服、越过配对权限、明文身份或写入重复，就停止生产使用并保留原配置与完整错误信息，不通过移除上下文和权限检查来“修复”。
